**Contrat de `rl.py` à écrire dans les énoncés 🔨** (les tests le vérifient, la docstring figée ne le dit pas toujours) :
- Entrées invalides → `ValueError` (jamais `IndexError` ni `TypeError`) : $\gamma$ hors de $[0, 1]$ (hors de $[0, 1)$ pour `value_iteration`) ; $\alpha$ hors de $]0, 1]$ ; $\varepsilon$ hors de $[0, 1]$, constant ou rendu par le calendrier ; température ≤ 0 ou NaN ; un compte (`n_episodes`, `max_steps`, `max_iter`, `batch_size`) < 1 ou booléen ; des récompenses qui ne sont pas 1-D (un scalaire compris), Q pas 2-D ou sans action ; un NaN dans les récompenses, Q, `Q_init`, `q_values` ou une récompense ; `q_values` vide ; un état, une action ou une action suivante hors de 0..n−1 (−1 refusé), booléen ou non entier (0,5) ; les entiers NumPy sont acceptés.
- Chaque tableau rendu est un nouveau tableau `float64` ; `discounted_return` et les erreurs TD rendent un `float` Python, `softmax_action` un `int` Python ; un épisode vide donne 0,0 et la forme `(0,)` ; listes et tuples d'entiers acceptés.
- `greedy_policy` : tableau d'entiers, ex æquo vers le plus petit indice.
- `softmax_action` : soustrait le max avant `exp` ; un seul tirage par appel, `rng.choice(len(q), p=probs)` (les tests comparent les tirages exacts).
- `q_learning_update`, `sarsa_update` : Q est un `ndarray` flottant (table entière refusée) ; ne modifient que `Q[state, action]`, en place, et rendent $\delta$ calculé avant la mise à jour (une transition vers soi-même utilise les valeurs d'avant) ; `terminated=True` → cible = `reward`, même si `Q[next_state]` n'est pas nul (masque et `next_action` alors ignorés) ; `next_mask` booléen ou 0/1 int8 ; masque de mauvaise longueur, ou tout faux sans `terminated` → `ValueError`.
- `train_tabular` : graine de `reset` de chaque épisode = `int(rng.integers(2**31))`, le premier tirage de l'épisode ; appelle `epsilon(i)` pour i = 0..n−1 et l'enregistre ; ne fait jamais de pas après la fin d'un épisode ; `lengths` = nombre d'appels à `step`, `returns` = somme non actualisée ; `max_steps` et `truncated` gardent l'amorçage, `terminated` non ; ex æquo au hasard par `epsilon_greedy_action` du ch. 11 ; avec `info["action_mask"]`, l'exploration porte sur `Q[s, légales]` puis se réindexe, les cases illégales ne bougent pas, le max du Q-learning utilise le masque de l'état suivant ; SARSA amorce sur l'action réellement jouée ensuite ; `Q_init` copié (forme fausse → `ValueError`) ; même `rng` → même résultat, aucun état aléatoire global.
- `evaluate_policy` : mêmes graines que `train_tabular` ; accepte une liste ou un tableau d'entiers comme table (refuse flottant ou 2-D) ; une politique appelable reçoit `(state, info)` ; rend exactement trois `float` Python (écart type ddof = 0).
- `value_iteration` : part de V = 0, balayages synchrones (`max_iter = k` rend exactement le k-ième itéré) ; s'arrête quand la variation est strictement sous `theta` (> 0) ; Q = un backup de plus de V ; accepte les `np.int64` de Gymnasium ; refuse un P vide, des états hors de 0..n−1, des actions vides ou inégales, des probabilités dont la somme s'écarte de 1 de plus de 1e-6, un état suivant hors limites ; ne modifie pas P.
- `ReplayBuffer` : `push` refuse un état de forme différente de `obs_shape` ; `sample` rend exactement les cinq clés, sans remise, uniforme sur les transitions stockées (après le retour au début aussi), des copies ; même `random_state` → mêmes mini-batches ; `batch_size` nul, plus grand que `len`, booléen, ou buffer vide → `ValueError`.
- Groupes de tests : `-k "test_discounted_return_ or test_returns_to_go_"` (26.14), `-k "test_greedy_policy_ or test_softmax_action_"` (26.19), `-k "test_q_learning_update_ or test_sarsa_update_"` (26.20), `-k "test_train_tabular_ or test_evaluate_policy_"` (26.21), `-k "test_value_iteration_"` (26.26), `-k "test_replay_buffer_"` (26.31).
