**Groupes `-k` des 🔨 et exigences des tests à écrire dans les énoncés** (rapport M, `s73/M/rapport.md`, et apprenant simulé V6, `s73/V6/rapport.md` ; les trois groupes couvrent les 186 tests, 33 + 111 + 42) :
- **B6.14**, `run_pytest_group("tests/test_chb6_explain.py", "test_shapley_values_")` :
  - `f` n'est appelée que sur des tableaux 2-D de forme `(n, M)`, jamais sur une ligne seule ; elle rend `(n,)` (la docstring ne dit pas ce qui se passe avec `(n, 1)` : écrire « une sortie de forme `(n,)`, par exemple `predict_proba(X)[:, 1]` », V6 B1) ;
  - toutes les lignes du fond comptent (pas de sous-échantillonnage, contrairement au `max_samples=100` de shap) ;
  - $v(S)$ est la moyenne de $f$ sur les lignes (f d'abord, la moyenne ensuite), et `base_value` = $v(\varnothing)$, un nombre (`float`) ;
  - $M$ = `max_features` est permis, seul $M >$ `max_features` lève ;
  - les entrées ne sont pas modifiées ;
  - **énumérer les $2^M$ coalitions et calculer chaque $v(S)$ une seule fois** (un dictionnaire masque → valeur) : les $M!$ ordres saturent la mémoire à $M = 12$. **Réglé dans les tests** (rapport M, « Retouches après l'apprenant simulé V6 ») : `f` y compte les lignes évaluées, et au-delà de `max(2·M·2**M·B, 500 000)` lignes l'appel est arrêté avec la première ligne « … compute v(S) once for each of the 2**M coalitions (an enumeration of the M! orderings without a cache of v(S) takes minutes) » ; un Shapley par permutations sans cache échoue donc en ≈ 11 s au lieu de passer en ≈ 4 min (224 s chez V6). L'énoncé de B6.14 doit le dire : 2**M appels à `f` sur B lignes ; au-delà d'environ 2·M fois ces lignes (500 000 au moins), les tests arrêtent la fonction et le disent ; budget qui laisse passer un v(S) recalculé pour chaque feature ou `f` appelée ligne par ligne.
- **B6.18**, `run_pytest_group("tests/test_chb6_explain.py", "test_integrated_gradients_ or test_grad_cam_")` :
  - `grad_fn` ne reçoit que des batches `(n, *x.shape)`, même avec `n_steps = 1` (pour un seul point, `point[None]` puis `[0]`) ;
  - `n_steps` compte les **intervalles**, c'est un entier (`2.5` : la docstring ne dit pas l'erreur, V6 B2 ; écrire « un entier ≥ 1 ») ;
  - les points sont $\mathbf{x}' + \alpha(\mathbf{x} - \mathbf{x}')$, le résultat multiplié par $\mathbf{x} - \mathbf{x}'$ et rendu en float, même pour un `x` entier ;
  - la baseline a exactement la forme de `x` : une forme diffusable est refusée ; les noms de règles de captum (`'riemann_trapezoid'`) sont refusés ;
  - **le trapèze de captum vaut celui de la docstring multiplié par $n/(n+1)$** (la note de la docstring figée, qui les dit égaux, est inexacte ; ligne §22 à écrire, stub non modifié) ; `left`, `right`, `midpoint` coïncident avec `riemann_*` au même nombre de points ;
  - Grad-CAM : poids = **moyenne** spatiale ; ReLU une fois, sur la somme pondérée ; chaque carte normalisée par son propre maximum des valeurs absolues, sans epsilon ; une carte nulle, y compris après la ReLU, reste nulle (pas de NaN) ;
  - les entrées ne sont pas modifiées.
- **B6.23**, `run_pytest_group("tests/test_chb6_explain.py", "test_group_rates_ or test_demographic_parity_difference_ or test_equalized_odds_difference_")` :
  - les clés sont les valeurs des groupes (`rates[10]` pour le groupe entier 10), dans l'ordre de `np.unique` ; scalaires Python ou NumPy acceptés (V6 B3) ;
  - `'n'` est un entier, les taux des floats, `nan` quand le dénominateur est nul ;
  - un seul groupe est permis pour `group_rates`, pas pour les deux écarts (`ValueError`) ;
  - NaN, 0,5, 2 ou −1 dans les labels ou les prédictions sont refusés ; les booléens et 0.0/1.0 sont acceptés (non testé, V6 B3 : le dire ou le laisser) ;
  - `group_rates` appelle `confusion_matrix(..., labels=[0, 1])` : sans `labels`, un groupe qui n'a qu'un seul label (sans positif, ou sans négatif) donne une matrice 1×1, et `tn, fp, fn, tp = C.ravel()` échoue (`ValueError: not enough values to unpack`) ; l'ordre de `C.ravel()` est `TN, FP, FN, TP` (disposition de scikit-learn, lignes = vérité ; le livre met TP en haut à gauche) ; les tests le disent maintenant dans leur message (« group 'q' has only the label 0 … confusion_matrix needs labels=[0, 1] ») ;
  - les deux écarts prennent max − min sur **tous** les groupes ; $\Delta_{\text{EO}}$ = le plus grand des deux écarts, et lève une erreur si un TPR ou un FPR est indéfini, là où fairlearn rend un nombre ;

## Points pour les énoncés et le contrat

- **captum** (rapport de l'auteur des tests, captum 0.9.0 installé à part) : la note de la docstring figée de `integrated_gradients` est inexacte ; `riemann_trapezoid` à $n + 1$ points vaut le trapèze de la docstring × $n/(n+1)$ (poids de somme $n/(n+1)$) ; `riemann_left/right/middle` au même `n_steps` coïncident. La fiche le dit (🕰️ des bibliothèques, et une ligne du tableau des pièges). L'énoncé de B6.18 doit le dire aussi ; ligne §22 à prévoir (stub non modifié).
- **fairlearn 0.15** rend un nombre (1,0 ou 0,5) pour un groupe sans positif ou sans négatif, là où la docstring exige `ValueError` : dit dans la fiche (🕰️ des bibliothèques).
- **Shapley par permutations** : un apprenant qui énumère les $M!$ ordres (`list(itertools.permutations(range(12)))`) sature la mémoire dès $M = 12$ (le défaut `max_features`), ce qu'aucune garde ne rattrape. Les notebooks doivent garder peu de features pour le Shapley exact de l'apprenant (8 features de California au plus, comme le prévoit le contrat ; jamais 12), et l'énoncé de B6.14 peut conseiller l'énumération des $2^M$ coalitions.
- Grad-CAM sur un ResNet de torchvision : `layer4` est en 1 × 1 pour une image CIFAR à 32 px. B6.20 doit agrandir les images (128 px : 4 × 4 ; 224 px : 7 × 7) ou viser `layer3`. Si le backbone du B1 est gelé, `register_hook` sur la sortie lève une erreur : il faut `images.requires_grad_()`.
- `maskers.Independent` a `max_samples=100` par défaut : B6.15 doit le passer à la taille du fond (déjà dit dans la fiche).
- Terme retenu **fiche modèle** (glossaire, B1) : le contrat dit encore « model card » (titre de section 206.11, concept, B6.28, `teaches`, `pro_skill`, résumé). La fiche garde le titre de section du contrat et écrit « fiche modèle » dans la prose : aligner le contrat (leçon de la session 63). De même « post-hoc » (titre 206.1) contre « post hoc » (glossaire).
- Formule ΔEO : la fiche l'appelle l'agrégation « pire cas » de fairlearn (`worst_case`).
- Numérotation : features de 1 à $M$ dans les formules, colonnes 0 à $M - 1$ dans le code (encadré 📐) ; le titre de B6.3 (« $x_1^2 + 3x_2$ ») est en numérotation 1, le docstring en numérotation 0 : l'énoncé doit dire laquelle il emploie.
